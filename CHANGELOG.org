* v0.6.2 -- 2026-11-07

The suite is green, and the pipeline deploys again.

Two assertions in =test/veritas/= were red, both before =v0.6.0= and neither the
fault of the code they were testing; because =v0.6.0= made the suite a gate
before the restart, each of them also stopped every push from reaching the
daemon -- =v0.6.0= and =v0.6.1= are tagged but were never deployed.

The doctype assert asked =string-contains= for its answer and handed it to
=assert-true=, which compares against =#t= itself: the doctype was found, at
index 600, and the assert failed on the index being an index.  It asks for
=#t= the way =mail-spec= already asks it.

The other counted every pending row and expected four where a fifth had been
queued by a fixture that comes after it, so it was measuring the file's own
growth rather than the question it was asking -- did the value that spells out
=DROP TABLE tasks= drop the table.  It counts the three rows that file queues
before the hostile value instead, which is exactly what the drop would have
taken, and no fixture added later can turn it red.

Nothing in the application changed: no source, no template, no schema, no
setting.

* v0.6.1 -- 2026-11-07

The picture in the manual is redrawn.

A pingwing message has named Work Sans and JuliaMono in its styles since before
=v0.6.0=, but the GIF in the manual was photographed on 2026-10-15, before that
change, so it showed the fallback stack -- the reader was shown type the mails
no longer ask for.  It is drawn again by =docs/make-demo-gif.sh= from the
templates themselves: the same three messages, the same three light frames and
the same dark pair, now set in Work Sans for the prose and JuliaMono for the
monospaced runs.  Set in the real faces, the type runs a touch wider than the
fallback did, so a sentence here and there wraps a word earlier; the frames,
their order, their delays and the pipeline are unchanged -- remote fonts are
still refused, so the picture shows what a client that refuses a web font sees,
with the two families resolved from the machine that drew it.

*Source Serif 4* is declared in =v0.6.0= and still unworn, so it does not appear:
the style that takes it will redraw this picture again.

Nothing else changed -- no source, no template, no setting, no schema.  The
suite is red for the two =templates-spec= assertions =v0.6.0= named, and they are
named there rather than fixed here.

* v0.6.0 -- 2026-11-07

A release about the terms, the pipeline and the type -- nothing about what
pingwing does with a task.

** MIT

pingwing is now licensed under the [[https://opensource.org/license/mit][MIT License]], where it was AGPL-3.0-or-later.
The full text is =LICENSE=, and =COPYING= is gone with the old terms.  Every
source file, config and migration now opens with the same four lines naming the
project, its =SPDX-License-Identifier= and the copyright holder, so a single file
copied out of this repository travels with its terms -- the fourteen-line AGPL
notice it replaces is in the licence file, where it belongs.  The documentation,
this file and the manual included, is [[https://creativecommons.org/licenses/by/4.0/][CC BY 4.0]].

For anyone who needs to know what the change costs them: the network-use
condition of the AGPL no longer applies from this version on, so an instance of
pingwing is now something you may run without offering its source, and nothing
else changed.  The terms of the versions up to and including =v0.5.0= are the
ones those versions were published under.

** The pipeline is GitHub Actions

A push to =trunk= is now collected by GitHub Actions (=.github/workflows/ci.yml=)
instead of Woodpecker (=.woodpecker/byggsteg.yaml=, removed), which asks the
jointhefreeworld [[https://codeberg.org/jjba23/byggsteg][Byggsteg]] service for a
job and follows its log to a green or a red build.  The workflow calls
[[https://github.com/jjba23/byggsteg-github][byggsteg-github]]'s reusable workflow
rather than carrying the steps here, and the job is =maak-test= and then
=pull-and-restart= on the =pingwing-daemon=: the suite is a gate now, where
before the push went straight to the running instance.  =CODEOWNERS= names the
maintainer, and =*.scm= is declared as Scheme so the repository is counted as one.

** Source Serif 4 is declared

The mail's type is now the house trio: *Work Sans* for the sans, *Source Serif 4*
for the serif and *JuliaMono* for the monospaced runs.  All three are libre (SIL
Open Font License 1.1) and declared from the project's own asset host, the
variable-weight files of the first two and the static pair of the third.  The
serif is available and declared, not worn: no element takes it yet, so every
message renders exactly as it did in =v0.5.0=, and =mail-serif-stack= is exported
for the style that will.

** Notes

Nothing in the API changed.  Every task type, template, setting and environment
variable of =v0.5.0= is the one this version takes, so an integrator has nothing
to do beyond deciding what the new terms mean for them.

The suite is not green: two assertions in =test/veritas/unit/templates-spec.scm=
fail -- the doctype one ("the message a client receives opens with it", a
=string-contains= answered with an index where a =#t= was expected) and a count
of 5 where 4 was expected -- and they failed before this release too.  They are
recorded rather than fixed here, which is why they are named.
